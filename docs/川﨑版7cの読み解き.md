## 0. まず全体のつくり（新アプリの設計に効く点）

1. **ほとんどの業務の中身（判断）は画面（ブラウザ）側にある。** サーバーは「受け取った行を書く」「つじつまを確かめる」だけ（GS:22）。
   CSVを読んで「新しい／変わる／変わらない／CSVにない」を決めるのは画面側（HTML:3348 analyze）。
2. **画面は最初に全データをまるごと受け取って、手元のメモリで組み立てる。** `getState` が全シートを返す（GS:203-210, 214-227）。工程一覧の絞り込み・並べ替え・在庫計算・集計は全部ブラウザ側（HTML:1236 rebuild, 1337 buildStock, 2587 sumFacts）。
   新アプリでは、件数が増えたらサーバー側の検索・集計（D1のSQL）に移す設計を考える必要がある。
3. **押した操作は「操作」として送る。** 画面でまず手元に当てて（先読み）、断られなければ送信待ちの列に入れ、裏で1件ずつ送る（HTML:1411 send, 1420 pump）。サーバーも同じ判定関数で再度確かめる。
   判定関数（applyActs / applyPlan / applyEdit / applyStock / applyMaster）は **コード.gs と index.html に同じ中身が2つある**。今回、二つを機械で比べて**完全に同じ**ことを確認した（15関数）。新アプリでは1つにまとめられる（サーバー側1か所でよい）。
4. データは Google スプレッドシート（シート＝表）。**全部の欄を「文字」で持つ**（バーコード13桁・日付が壊れないように。GS:110-120）。日時は `YYYY/MM/DD HH:MM`（日本時間・秒なし・タイムゾーン情報なし）、日付は `YYYY/MM/DD`、旗は `'1'` か空。
5. 更新番号（`設定.更新番号`、以下 ver）が全体で1つ。何か書くたびに +1（GS:275, 454 など）。画面は20秒ごとに ver を聞いて、違えば全部読み直す（HTML:379 POLL_MS, 4126）。
6. 手元で開いたとき（Apps Script の外）は `LOCAL`（ブラウザの localStorage）で代わりに動く試験用の仕組みがある（HTML:398-505）。新アプリには不要。

### 1-12. ID と13桁バーコードの作り方

- **取り込みのとき**：`設定.次の番号` を元に `A`/`I`/`P`/`M`/`S` ＋ 6桁（例 `I000123`）。全種類で1本の連番を使う（HTML:3392-3393）。サーバーは `max(元の値, 画面が使った最後の番号)` で保存（GS:276）。
- **画面で新規**：`kNewId(接頭字)` ＝ 接頭字 ＋ `w` ＋ 現在時刻の36進 ＋ 連番36進 ＋ ランダム3文字（HTML:2738）。接頭字：案件 `A`、品目 `I`、工程 `P`、作業 `W`、基本の一覧 `K`。
- **サーバーが作る**：在庫の動き `M<操作の札>-n`、出荷 `S<札>-n`、作業ログ取り込みの作業 `W<札>-n`、ごみ箱 `Z<札>-n`。
- **操作の札（opId）**：`Date.now()` の36進＋ランダム6文字（HTML:510）。同じ操作が2回届いても1回分にする（冪等）ための印。サーバーは Script Properties の `OPS` に直近300件を覚える（GS:241-245, 278）。
- **13桁バーコード（画面で付けるもの）**（GS:776-792, HTML:818-833）：
  `頭「20」` ＋ `10桁の連番（0埋め）` ＋ `チェック数字1桁`。
  チェック数字は標準の EAN-13/JAN：左から奇数桁（1番目…）×1、偶数桁×3 の合計の1の位を10から引く（`(10 - sum%10) % 10`）。
  例：連番1 → `2000000000015`。
  頭を「20」にしたのは 2026-10-22 に作業者と相談して決めた（GS:34）。エムネットの番号は `1334…` なので頭を変えればぶつからない。
  ほかの品目と同じ番号なら次の番号に進む（ごみ箱の中の品目は見ない）。連番が10桁を超えたらエラー。
  **番号が付くのはサーバーに保存したとき**（画面側で先読みするときは空のまま、GS:918 `if (ctr)`）。ラベル印刷は番号が付いてから（HTML:3148）。
  ラベルは EAN-13 をSVGで描いて Brother QL-800 に印刷（HTML:3086-3163、サイズ 62×29 / 62×100 / 62×40 / 自由）。ラベルの内容は 社内管理番号・数量・図面番号・品名・納期・バーコード。
- 取り込むCSVの行は、バーコード番号（エムネットの13桁）が空なら飛ばす（2-4）。

## 2. CSV取り込み

### 2-1. 3種類のCSV

| 取り込み先 | 画面の場所 | CSV | 先に必要なもの |
| --- | --- | --- | --- |
| 案件・品目・工程 | CSV取り込みタブ（ドロップ枠） | エムネット「案件一覧」書き出し（カテゴリー2＝製造技術で絞る） | なし |
| 作業 | 同タブの「作業ログCSVから作業を写す」 | エムネット「作業ログの書き出し」 | **案件一覧CSVを先に**（品目・工程が無いと写せない） |
| 完品在庫数 | 在庫タブの「作業ログCSVを読み込む」 | 同じ「作業ログの書き出し」 | 5段目最初の日は案件一覧CSVより先 |

### 2-2. 文字コードの扱い（HTML:3219-3224, 2554-2558, 3575-3580, 3185-3189）

- 案件一覧CSV（`decode`）：まず Shift_JIS で読む。文字列に「社内管理番号」があればそれを採用。無ければ UTF-8（先頭BOMは外す）で読み、「社内管理番号」があればそれを採用、無ければ Shift_JIS の結果のまま。
- 作業ログCSV（2つの画面とも）：Shift_JIS で読み、「社内管理番号」を含めばそれを採用、でなければ UTF-8（BOM除去）。
- リバテック休日.txt：UTF-8 で読み、文字化けの印（�）があれば Shift_JIS で読み直す。
- CSVの読み方（`parseCsv`、HTML:3202-3218）：ダブルクォートで囲んだ欄の中の改行・カンマ・`""` に対応。空行は捨てる。
- **エクセルで開いて保存したCSVは壊れる**（13桁バーコードが指数表示になる）。数字だけでないバーコードは警告が出る（2-4）。

### 2-3. 案件一覧CSVの形（位置で読む。HTML:3351-3354, 3244-3274）

確認しているのは次の3点だけ。**列は見出しの名前ではなく「位置」で読んでいる**。
- 2行目（0から数えて `rows[1]`）の1列目が `社内管理番号`、12列目が `バーコード番号`、列数が64以上であること（HTML:3351）。満たさないと「案件一覧のCSVではない」で止まる。
- 1行目は読み捨て（中身はコードから分からない。**未確認事項**）。
- 3行目が「全部数字」の行（1列目・12列目とも数字だけ）なら「欄の文字数の行」として読み飛ばす（HTML:3354）。

### 2-5. 照合と「新しい・変わる・変わらない・CSVにない」の判定（HTML:3348-3381）

1. 各行を `recOf` で 案件・品目・工程 に分け、`normRec`（名寄せ、2-7）をかける。
2. 品目はバーコード番号で既存と突き合わせる（`DB.byBc`）。
3. 既存が**無い** → 「新しい」。ただし次の「古い案件」なら最初はチェックを外す。
4. 既存が**ある** → `mergeRec`で次を比べて、違いが1つでもあれば「変わる」、無ければ「変わらない」。
   - 品目の `I_CMP`（バーコード番号・区分・区分2・社外バーコード・図面番号・品名・単価・数量・最終納期・リンク・ノウハウ・備考・隠す・納品情報）
   - 案件の `A_CMP`（社内管理番号・営業担当・顧客発注番号・顧客・顧客の担当者・受注日・一括納期・リンク・備考・注釈・隠す）
   - 工程は `エムネットの枠` で突き合わせ、`P_CMP`（順番・社内外注・工程名・担当者・機械・開始予定・納期・開始日時・完了日時・完成数量・検査日・検査者・工程単価・基準時間・備考・その他）を比べる。CSVにだけある枠は「工程を足す」、画面にだけある枠は「工程を消す」。
5. 今ある品目でCSVに**無い**もの → 「CSVにない」（初期はチェックなし。**消すときだけ人がチェック**）。ただし `登録元` が入っている（この画面で登録した）品目は比べない（HTML:3379）。
6. 「変わる」には、何が変わったかを1行ずつ文章で付ける（例：`工程 旋盤：開始日時 空→2026/10/22 08:15`、`工程を足す：…`、HTML:3288-3308）。

### 2-6. エムネットの日時と、この画面で押した日時のぶつかり（HTML:3280, 3298-3302）

- 「変わる」のとき、工程の行は**CSVの内容で作り直して**入れ替える（その品目の工程を全部消して入れ直す、GS:258-261）。ただし次を引き継ぐ：
  - 開始日時・完了日時・完成数量：**CSVが空で、画面に入っていれば消さない**（現場が押した実績を守る、`KEEP`）。
  - 開始した人・完了した人：**日時がCSVと同じ間だけ残す**。エムネットで別の日時になったら、押した人は空にする。
  - 不良数・コメント・不良の理由：エムネットに無い欄なので、画面の値を必ず残す。
  - 工程ID：エムネットの枠が同じなら、前の工程IDを引き継ぐ（作業・出荷・実績記録が切れない）。
- つまり：**CSVに日時があれば、画面で押した日時を上書きする**（押した人は空になる）。**CSVが空なら画面の日時は残る**。エムネットで「完了を取り消した」ことは画面に伝わらない（空は上書きしない）。
- 在庫の動きとの連動（HTML:3314-3334）：既にある品目で、工程が「画面では未完了」→「CSVで完了」に変わったとき、
  - 製品になる工程（出荷の1つ手前）なら製品を増やす（数＝完成数量、無ければ品目の数量）。ただし「在庫から出した」品目は増やさない。
  - 出荷の工程が完了なら、出荷を1行記録して製品を減らす（数＝品目の数量−これまでの出荷）。
  - **初めて入る品目は、すでに終わっている工程でも在庫の動きを作らない。**

### 2-7. 名寄せ（基本の一覧による置き換え）を比べる前にかける（HTML:3338-3346, GS:1062-1079）

比べる前に、CSVの次の欄を「基本の一覧」の表で置き換える（表に無い書き方はそのまま）：
顧客（種類＝顧客）、営業担当（作業者）、各工程の 工程名（工程名）・機械（機械）・担当者・外注先（社内なら作業者、外注なら外注先）。
`-` `ー` `－` `―` は「担当なし」の印で置き換えない（`NO_NAME`）。
置き換えた件数は画面に「名寄せで、CSVの書き方を ◯か所そろえてから比べました」と出す。エムネットの中身は変わらない。
置き換えない欄：検査者・発注者など。

### 2-8. 古い案件（HTML:377, 3371）

新しい品目のうち、`最終納期 < 2025/01/01` **かつ** どの工程も完了していないものを「古い案件」として、最初はチェックを外す。
**手順書は「2024年より前」と書いているが、コードは `OLD_DUE = '2025/01/01'`（2025年より前）。** 画面の文言もコードの値から作られる（HTML:3495）。どちらが正しいか未確認。

### 2-9. 保存の流れ（HTML:3384-3473, GS:234-284）

1. 「取り込む」→確認ダイアログ。
2. この端末の送信待ちを先に送り切る（30秒で終わらなければ中止）。
3. 最新を読み直し、CSVを読んだあとに ver が変わっていたら**自動で比べ直し**て、もう一度確認させる。
4. 新しい案件IDは `社内管理番号` で既存案件を探して付ける。案件に変更が無ければ案件行は送らない。
5. 品目300件（`CHUNK`）ずつに分けて `importBatch` で送る。最初の1回に案件行、最後の1回に「消す品目・案件」「出荷・在庫の動き」「取り込み履歴」を付ける。1回ごとに `baseVer` を最新にする。
6. サーバーは、`baseVer` が今の ver と違えば「データが変わりました」で断る。同じ操作の札が既に来ていれば何もせず今の状態を返す。ロックを30秒待っても取れなければ断る。
7. 「CSVにない」で消す品目は**ごみ箱へ入れてから**消す（'取り込みで消した'）。品目が1つも無くなった案件も消す（GS:253, HTML:3430-3434）。
8. 途中で止まっても、保存できた分は残る。同じCSVをもう一度選べば残りだけが出てくる。**全体を1回で戻す（トランザクション）仕組みは無い。**

### 2-10. エムネットの作業ログCSV（2つの使い道）

作業ログから「作業」を写す（`parseWorkLog`、HTML:3532-3561）
- 必須の見出し：`バーコード` `工程名` `開始時刻` `終了時刻` `作業者` `完成数量`（無ければ止める）。あれば使う：`機械名`。
- 工程名が `完品在庫数` `材料在庫数` の行は写さない（在庫タブで読む）。
- 開始時刻が空なら終了時刻で代用。日時は先頭16文字（`YYYY/MM/DD HH:MM`）を使い、形が合わなければ「日時が読めない」で飛ばす。
- 「同じ行」の印（`もと`）＝ `バーコード|工程名(元の書き方)|開始時刻|終了時刻|作業者|完成数量#n`。同じ中身が複数行あるときは `#1,#2…`。既に写してあれば「もう写してある」。
- 品目はバーコードで探す（無ければ「品目が無い」）。工程は**名寄せした工程名**で探す（無ければ「工程が見つからない」）。同じ名前の工程が2つ以上あれば**先の方**に入れる。
- 作業者・機械名も名寄せしてから入れる。工程の開始・完了は変えない。不良数・コメントは空で入る。400件ずつ `procAct`（op=`wImport`）で送る。
- サーバー側でも同じ印を二重に入れない（GS:538-549）。

完品在庫数を写す（`parseMnetLog`、HTML:2507-2537）
- 必須の見出し：`社内管理番号` `バーコード` `図面番号` `品名` `工程名` `開始時刻` `終了時刻` `作業者` `完成数量`。あれば使う：`備考`。
- 工程名が `完品在庫数` の行だけ拾う。完成数量は全角→半角にして数でなければ「読めないので飛ばす」。
- 同じ行の印＝`バーコード|開始時刻|終了時刻|作業者|数#n`。図面番号ごとに合計を出して、エムネットの「在庫管理」画面と合うか目で確かめさせる。
- 「最初の数」：この画面の計算の最初の数が無い図面番号には、エムネットの合計と同じ数を入れる（チェックが入ったまま「写す」）。
- 前に写した行のうち、このCSVの同じ期間に無いものは警告のみ（写した行は残す）。

## 3. 業務のきまり

### 3-1. 工程の状態（HTML:1258-1259, 2016-2022, 1757）

- 状態は**日時から決まる**：`完了日時` があれば完了、無くて `開始日時` があれば作業中、どちらも無ければ未着手。状態の列は持たない。
- 品目の「今の工程」(`_cur`) ＝ **順番どおりで、最初に `完了日時` が無い工程**（後ろの工程が先に完了していても、この定義は変わらない）。品目が「全部終わった」(`_done`) ＝ 工程が1つ以上あって `_cur` が無い。工程が0個の品目は「終わっていない」にも「終わった」にも当たらない（`_done`が偽）。
- 操作（GS:576-616）：
  - `start`：完了済みなら「もう完了していました」、開始済みなら「ほかの人が先に開始していました」で**断らず飛ばす**（知らせだけ返す）。
  - `done`：完了済みなら飛ばす。数量は数字必須（空不可）。開始が無ければ**同じ時刻で開始も入れる**。完成数量・不良数・コメント・不良の理由を一緒に保存。
  - `undoStart`：画面が見ていた開始日時（`base`）と違えば断る。完了済み・出荷記録あり・作業の記録ありは断る。
  - `undoDone`：画面が見ていた開始・完了日時と違えば断る。完成数量・不良数・不良の理由を空に戻す。開始を押さずに完了していたと分かれば（`alsoStart`）開始も消す。出荷の工程なら出荷の記録を全部取り消す。
- まとめて完了：選んだ品目の「今の工程」を1回で完了（数量は各品目の数量。出荷の工程は残りの数で出荷を記録）。**1件でも誤りがあれば全体を断る**（GS:618）。
- 押した時刻 `at` は**端末の時計**（`YYYY/MM/DD HH:MM`）。形が違うとサーバーが断る（GS:486-487）。作業者名が空でも断る（作業者はログインとは別に右上で選ぶ。端末に覚える）。

### 3-2. 工程の中の「作業」（7段目、GS:482-733）

- 1つの工程に作業を何回でも（何人でも同時でも）付けられる。作業の開始・終了と、工程の開始・完了は別。
- `wStart`：作業を始める。工程がまだ始まっていなければ**工程も同じ時刻で開始**にする。完了済みの工程には足せない。同じ作業IDが既にあれば飛ばす。
- `wAdd`：終わった作業を1回で記録（開始＝終了＝押した時刻）。
- `wEnd`：作業を終える（完成数・不良数・コメント・機械・不良の理由）。ほかの人が先に終えていれば飛ばす。
- `wEdit`：開始・終了日時や数を直す。**画面が見ていた行の印（ハッシュ）と今が違えば断る。** 終了が開始より前なら断る。
- `wUndo`：取り消す（行は残し、取り消した日時・人を入れる）。
- `wImport`：エムネットの作業ログから写す（2-10）。
- 「工程の中の作業は、工程が全部終わったら自分で工程の完了を押す」。作業を終えても工程は自動で完了にならない。

### 3-3. 作業の合計が工程の数量に入る（7段目c、GS:709-731）

- `wStart` 以外の作業の操作（`wAdd`/`wEnd`/`wEdit`/`wUndo`）のあと、その工程について、取り消していない作業のうち数が入っているものを合計して工程に入れる：
  - 完成数量 ＝ 完成数の合計（完成数が入っている作業が1つでもあるとき）
  - 不良数 ＝ 不良数の合計（0なら空）
  - 不良の理由 ＝ 不良数がいちばん多い理由
- 作業の数がみんな無くなり（取り消し等）、工程がまだ完了していなければ、工程の完成数量・不良数・不良の理由を空に戻す。
- **出荷の工程は合計で上書きしない**（出荷した数の合計のため）。エムネットから写した作業（`wImport`）では工程の数を変えない。

### 3-4. 出荷の工程の見つけ方（GS:955-974, HTML:1002-1016）

`stockRole(区分, 工程を順番に並べたもの)`：
1. 区分が `在庫管理` の品目は対象外（null）。
2. **数に関係しない工程名を除く**：`材料発注・材料入荷・材料・帳票発行・ダミー工程・完品在庫数・材料在庫数・在庫`（`NOQTY`、名前が**完全一致**。前後の空白は除く）。残りを `q`。`q` が空なら対象外。
3. `q` の中で最初に「出荷の工程の名前」に当たるもの → 出荷の工程（`ship`）。出荷の工程の名前＝**名前に「出荷」を含み、かつ「目視」「検査」を含まない**（`isShipName`。「分納出荷」「選別出荷」は出荷、「出荷目視」「出荷検査」は出荷ではない）。
4. 当たるものが無ければ**`q` の最後の工程**を出荷の工程とみなす（ギガフォトン品の「目視、梱包」など）。
5. 製品になる工程（`prod`）＝ 出荷の工程の**1つ手前**（`q` の中で）。1つ目が出荷なら `prod` は空（在庫から出すだけ）。
6. `q` ＝ 出荷の工程までの工程（出荷より後ろは含めない）。

### 3-5. 出荷と分納（GS:581-604, 696-706, HTML:1906-1976）

- 出荷の工程の札を押す（またはタブ「出荷」の「🚚 出荷を記録」）と出荷の入力窓が出る：出荷日（既定＝今日）、出荷する数（既定＝残り）、配送業者（候補：ヤマト運輸・佐川急便・西濃運輸・福山通運・日本郵便・自社便・持参）、伝票番号、荷物の個数、時間指定、お届け先、担当者（既定＝選んだ作業者）、備考、「これで全部」、「在庫から出した」。
- 「これで全部」あり → `done`（工程を完了にし、完成数量＝出荷した数の合計）。なし → `ship`（**分納**。工程は作業中のまま。何回でも記録できる）。
- 出荷した数 ＜ 数量 のまま「これで全部」→確認。合計が数量に届いたのに「これで全部」が無い → 確認。
- 出荷の数は 1 以上必須（ただし0個の「これで全部」だけは完了のみ）。出荷日の形は `YYYY/MM/DD` 必須。
- 出荷を記録すると 出荷 に1行、在庫の動き に **−数**（種類＝出荷）を足す。
- 「在庫から出した」（`在庫から`＝1）：この品目の完了で増やした分があれば、その分を**戻す**（−`net`）。以後、この品目の完了では製品を増やさない。
- 出荷の取り消し（`unship`）：出荷に取り消し印を付け、在庫の動きに＋数（種類＝出荷の取り消し）を足す。工程の完了はそのまま。
- 出荷の工程の「完了を取り消す」：その品目の**出荷の記録を全部取り消す**（確認ダイアログで知らせる）。
- 出荷の工程の「開始を取り消す」は、出荷の記録があれば断る。
- タブ「出荷」の予定日 ＝ 出荷の工程の `納期` → `開始予定` → 品目の `最終納期`（入っているものを順に。日付10桁だけ、HTML:2364-2369）。範囲：今日まで／今週（月曜始まりの日曜まで）／来週まで／まだ出荷していない全部。遅れ（予定日 < 今日）は赤で出る。

### 3-6. 在庫の計算（HTML:1337-1377, 2416-2455）

画面は 図面番号ごとに次の列を出す。
- **エムネットの写し** ＝ 在庫の動きのうち帳簿＝`エムネット` の数の合計（作業ログの「完品在庫数」の±を足したもの）。
- **この画面の計算** ＝ 帳簿＝`画面` の数の合計 ＝ 最初の数 ＋ 出荷の1つ手前の工程が完了した数（取り込みで入ったエムネットの完了を含む）− 出荷した数 ＋ 数を直した分。
- **差** ＝ 計算 − 写し（両方がある図面番号だけ）。
- ★＝どちらが「正」か（`設定.在庫の正`）。切り替えは「この画面の計算を正にする」（切り替えのとき、差のある図面番号を先に「エムネットの数に合わせる」）。
- **仕掛品**：まだ出荷の工程が完了していない品目について、`q` の中で**最後に完了した工程**を探し、その位置が「製品になる工程（`q`の後ろから2つ目）より前」のとき、その品目の数を「工程名 まで」ごとに足す。数＝その工程の完成数量、無ければ品目の数量。`q` に入らない工程（材料発注・材料入荷・帳票発行・ダミー工程・完品在庫数・材料在庫数・在庫）と、区分「在庫管理」の品目は数えない。
- **出荷待ち**：出荷の工程が未完了の品目の `max(0, 数量 − 出荷済み)` の合計。**まだ1つも工程が始まっていない品目も入る**（名前は「出荷待ち」だが実質「まだ出荷していない残数」）。
- 「数を直す」：増減数（−も可）と**理由が必須**。数は0にできない。種類＝数を直す。
- 「エムネットの数に合わせる」：差をそのまま「数を直す」で入れる。
- 画面の既定は「在庫か仕掛品のある図面番号だけ」表示。

製品が増える・減るタイミング（サーバーが在庫の動きを書く）：
| きっかけ | 在庫の動き |
| --- | --- |
| 製品になる工程を完了（`done`、在庫から出した品目でなければ、数＞0） | ＋完成数量（種類＝工程の完了） |
| その工程の完了を取り消す | −（その工程から来た合計）（種類＝完了の取り消し） |
| 出荷を記録 | −出荷数（種類＝出荷） |
| 在庫から出した出荷 | 加えて −（完了で増やした分）（種類＝在庫から出した…） |
| 出荷を取り消す | ＋（種類＝出荷の取り消し） |
| 取り込みでエムネットの完了が新しく入る | 上の表と同じ（種類＝取り込みの完了／取り込みの出荷） |

### 3-7. 休日の使いみち（HTML:2097-2112, 3174-3199, GS:296-311）

- 休日 ＝ 土日＋ `休日` シートの日付（`isOff`）。土日は書かなくても休み。
- **使うのはガントだけ**：①日付の見出しを灰色にする ②「休日を数えない」にチェックのとき、工程を動かすとき**後ろの工程を稼働日数でずらす**（`addWork`/`workBetween`）。在庫・集計・出荷予定には使わない。
- 登録：基本の一覧の「休日」タブで1日ずつ足す・外す（`masterAct` kind=`hol`）、または `リバテック休日.txt`（1行に1日。`2026/4/29 # メモ`、区切りは `/ - .`）で**丸ごと入れ替え**（`setHolidays`。ver比較なし・操作の札を使わない・実績記録に残さない）。

### 3-8. 名寄せ（基本の一覧、GS:1034-1153）

- 種類：工程名・作業者・機械・外注先・顧客・不良の理由。
- 「名前」と「別の書き方（｜区切り）」を持つ。保存すると、**今ある案件の 顧客・営業担当、工程の 工程名・機械・担当者・外注先・開始した人・完了した人・不良の理由 を書き換える**（作業の行・出荷・実績記録は書き換えない。集計で見るときにそろえる）。
- 検査：同じ種類の中で、名前や別の書き方が2つの項目に入っていたら断る。名前に「｜」は使えない。並びは数字。名前を空にできない。
- 他人が先に直していた（行の印がずれた）ら断る。
- 工程名の名寄せで、「在庫の計算で特別扱いの名前」が別の扱いにそろうと、確認に「※」が出る（HTML:3745）。
- 画面右上の作業者の選択肢は、基本の一覧の作業者があればそれ。一覧が空なら今あるデータに出る名前（HTML:1533-1553）。

### 3-9. 集計（7段目b〜c、HTML:2573-2733）

- 期間（既定＝今月1日〜今日）とまとめ方（工程名・図面番号・作業者・機械・不良の理由・顧客・日・月）。
- 1件ずつの材料（`sumFacts`）：期間に入る**取り消していない作業**（日付＝作業の終了日、作業中は開始日）。物が動かない工程（`NOQTY`）の作業は数えない。
- 「作業を分けずに完了した工程も入れる」（既定ON）：作業が1つも無い完了済みの工程は、工程の完了数量・不良数を1件として入れる（時間は無し。日付＝完了日、人＝完了した人か担当）。
- 作業時間 ＝ 終了 − 開始（**休み時間も入る**）。作業中・終了が開始より前のものは時間に入れない。
- **10時間の上限**：`LONG_MIN = 600`分。「エムネットから写した作業（`もと`あり）で、1回600分を超えるもの」は、押し忘れとみて**時間に入れない**（数は入れる）。チェックで外せる。**この画面で記録した作業は長くても入れる**（無人運転があるため。押し忘れは作業の「直す」で直す）。基準時間との比べでも同じ扱い（HTML:2654）。
- 列：作業（件数）／作業時間／1個あたり（分）＝時間÷（完成＋不良）／完成（良品）／不良／不良率＝不良÷(完成＋不良)／多い不良の理由。「不良の理由」でまとめるときは別の列（不良数・割合・作業・多い工程）。
- 基準時間との比べ：基準時間が入っている工程のうち期間に作業があるもの。作業時間は**その工程の作業の合計（期間外も入れる）**。
- 出力：CSVで保存（BOM付きUTF-8）／表をコピー（タブ区切り）。

### 3-10. ぶつかり対策（楽観的ロック）と「保存できなかった操作」

サーバー側（GS）：
1. **全体で1つのロック**（`LockService.getScriptLock()`）を取って書く。30秒待って取れなければ「ほかの人が保存中です」（GS:236-237 ほか）。
2. 操作の札（opId）で**二重送信を無視**（`OPS`直近300件）。
3. **更新番号 `baseVer`**：`importBatch` だけが厳密に比べる（違えば断る）。
4. **画面が見ていた値と今の値を比べる**（楽観的ロック）：
   - 工程の開始取り消し・完了取り消し：`base:{s,e}`＝開始・完了日時（GS:606, 612）
   - ガントの予定変更：`base:{s,e}`＝開始予定・納期。1本でも違えば全体を断る（GS:751）
   - 案件の保存・ごみ箱へ：`editBase_`（編集できる欄全体のハッシュ。案件・品目・工程の編集欄が対象。GS:802-811, 858, 922）
   - 作業を直す：行全体のハッシュ（GS:527）
   - 基本の一覧：行のハッシュ（GS:1097, 1107）
   - **開始・完了は「先にやられていたら飛ばす」**（断らない）。
5. 1つでも誤りがあれば、その操作（まとめて完了など）は**全部断る**（何も書かない）。
6. 書き込みは、まず変わった行だけ（40行超か削除があるときはシート全体を書き直し、GS:33, 401-415）。

画面側（HTML:1396-1522）：
- 押したら**すぐ画面に出す**（手元で先に当てる）。送信待ちの札は点線＋「保存待ち」。
- 送信待ちの列 `Q` は localStorage（`kotei.queue`）に控える。閉じても次に開いたとき続きから送る。
- 送れなかったときの扱い（`canRetry`）：**エラー文に日本語（ひらがな・カタカナ・漢字）が1文字でも入っていれば「断られた」とみなす**（ただし「保存中」を含むものは例外）。日本語が無ければ（通信エラーなど）「つながらない」とみなして**同じ札で**送り直す（待ち 5・10・20・40・60秒…）。20秒たっても送れないと赤い帯「まだ記録されていません」。
- 断られたもの：列から外して **「保存できなかった操作」**（localStorage `kotei.failed`）に入れ、ページ上部に出す。「もう一度送る」（今の中身の上から入れ直して新しい札で送る。`retryNG`）か「取りやめる」。
- CSV取り込み中は送信を止め、前に押した操作を先に送り切る。
- iPad の Safari は閉じると localStorage が消えることがあるので「点線の札が残っている間は閉じない」（手順書の注意）。

### 3-11. ほかのきまり

- **案件の編集**（GS:839-950）：社内管理番号は必須。受注日・一括納期は日付形式、数量・単価・基準時間は数字、図面番号か品名のどちらかが必須、工程は名前必須・社内か外注、開始予定 ≤ 納期。編集で消した品目はごみ箱へ。画面から消す工程は**開始・完了の記録があっても消える**（確認が出る）。「前回の並びを写す」：同じ図面番号の前の品目の工程の並びをコピー（予定日は空に）。

- **全案件消去**（`clearAllCases`、GS:1219-1236）：先に控えを作ってから、案件・品目・工程・作業・実績記録・出荷・在庫の動き・ごみ箱・取り込み履歴を全部空にする（基本の一覧・休日・設定は残す）。

### 5-3. 【最重要】工程一覧：案件ごとの「今どの工程か」の見え方（HTML:1666-1695, 2013-2049）

1行＝品目1つ。行の中身は左右2つ（スマホは縦に積む）。

```
┌───────────────────────────────────────────────────────────────────────┐
│ ☐ 管理番号 [区分] [隠す]   │ [材料入荷]›[NC旋盤 MC1]›[研磨]›[目視、梱包]›[出荷🚚]   │
│   図面番号 品名            │   緑(完了)   黄(作業中)   青枠(次)   灰    灰       │
│   顧客・N個・納期 日付     │          └─ 札の下に小さく「機械」か「担当者」        │
└───────────────────────────────────────────────────────────────────────┘
        納期を過ぎて終わっていない行は左に赤い縦線、納期の日付が赤い太字
```

- **左**：チェック（今の工程があるときだけ）、社内管理番号（太字）＋区分・隠すの札、図面番号＋品名、顧客・数量・納期（遅れは赤）。行を押すと詳細（下に開く）。
- **右**：その品目の工程を**順番どおりに全部**、札（ボタン）で横に並べ、札の間に「›」を置く。折り返す。
- 札の見た目（`rowHtml`）：
  - 完了＝緑地、作業中（開始あり・完了なし）＝黄地＋太字、**「次」＝最初の未完了工程のうち、まだ開始していないもの＝白地に青の枠・太字**、それ以外の未着手＝灰地。
  - 外注の工程は札の頭に紫の小さい「外注 」。
  - 出荷の工程は札の後ろに「🚚」。
  - 画面でまだ保存していない操作は点線の縁（「保存待ち」）。選んでいる札は青い外枠。
  - 札の文字＝工程名。その下に小さく機械名（無ければ担当者。`-` は出さない）。
  - 作業中の人がいれば「作業中N人」の小さい札（同じ人が2つ始めていても1人）。
  - 札にマウスを載せると工程名・担当・機械・開始予定・納期・開始（人）・完了（人）・作業中の人と時刻。
  - 工程が0個なら「工程なし」と出す。
- 今の工程は `_cur`（最初に完了日時が無い工程）。**後ろの工程が先に終わっていても、前の未完了が「次」になる**（札は完了のものは緑のまま）。
- 並び順：最終納期の昇順（納期が空なら最後）、同じなら社内管理番号。1回に200件表示、「さらに200件出す」。
- 絞り込み（localStorageに覚える）：さがす（管理番号・図面番号・品名・顧客・バーコード・顧客発注番号）／**今の工程**（`_cur`の工程名。選択肢に件数付き）／担当・外注先（`_cur`の担当）／機械（`_cur`の機械）／区分／状態（既定＝終わっていない／全部終わった／すべて）／納期から・まで／隠したものも出す／条件を消す。
- 札を押すと、その品目の下に**小窓**が開く（開始・完了・取り消し・作業・出荷・コメント）。品目の行の左のチェックで「今の工程をまとめて完了」。
- 一覧の上：「◯◯さんの作業中 n件」カード（押すとその工程の小窓を開き、さがす欄をその管理番号に絞る。「← 一覧に戻る」で元の絞りに戻る）、ほかの人の作業中は折りたたみ。
- 詳細（品目の行を押す）：バーコード・顧客発注番号・受注日・営業担当・区分2・最後に取り込んだ日時／工程の表（順・社内/外注・工程・担当・機械・開始予定・納期・開始（人）・完了（人）・完成数量・不良数・作業の件数・コメント備考）／ノウハウ・備考／作業の記録の表／この画面で押した記録（新しい30件）。

新アプリで「一目で見たい」点は、(1)全工程が順に並ぶ、(2)色で完了・作業中・次・まだが分かる、(3)外注・出荷が分かる、(4)納期遅れが分かる、(5)誰がいま作業中か、の5つ。

## 6. 危ない点・おかしな点

### 6-1. 誰が使えるか（安全面）

- `doGet` は**認証もアクセス確認もしていない**（GS:63-67）。画面を返すだけ。守りは**デプロイ設定だけ**：コードの注釈には「次のユーザーとして実行：自分」「アクセスできるユーザー：rvatec.com 内の全員」とある（GS:20-21）。これはコードでは確かめられない（実際のデプロイ設定は未確認）。
- 「自分として実行」なので、使う人のデータ権限ではなく**スクリプト所有者の権限**で全部のシートを読み書きする。ドメイン内の誰でも、全客先名・単価・出荷先・伝票番号を見られる（`getState` が全部返す）。
- 末尾が `_` でない関数は、ブラウザの開発者ツールから `google.script.run` で**だれでも直接呼べる**。つまりドメイン内の誰でも次ができる：`clearAllCases()`（案件ほぼ全部消去。ただし消す前に控えを作る）、`stopBackup()`（毎晩の控えを止める）、`setupBackup()`、`backupNow()`、`importBatch`/`procAct` などに任意のJSON（作業者名も好きな名前）を送る。新アプリでは、管理系の操作は権限で分けること。
- 「作業者」は**自分で選んだ名前**で、ログインとは別（共用IDを何人かで使うため）。他人の名前で押せてしまう。`アカウント` 列（メール）は `Session.getActiveUser().getEmail()`。デプロイ設定によっては空になる（GS:1248）。
- 手元ブラウザ用の `LOCAL`（localStorage にデータを入れる）が本番画面にも入っている。Apps Script の外で開いたときだけ動くが、新アプリには持ち込まない。

### 6-2. 個人情報・機密

- 顧客名・顧客の担当者・単価・工程単価・お届け先・配送伝票番号・社員名（作業者・メール）。決済情報・患者情報は無い。
- 毎晩の控え（Drive）は丸ごとコピー。共有しない前提（手順書）。コードはフォルダを作るだけで共有制限は設定していない。
- ごみ箱・実績記録・作業に社員のメールアドレスが残る。

### 6-3. データが消える・ずれる恐れ

1. **品目・案件を消しても、作業・出荷・在庫の動き・実績記録は残る**（外部キーの整理が無い）。画面に出す側は「（消えた品目）」と出すが、集計や在庫の「この画面の計算」には残る（在庫の動きは図面番号で足すため）。
2. CSV取り込みで「変わる」とき**その品目の工程を全部入れ替える**。エムネット側で工程の枠が減る・並びが変わると、画面で入れた 作業 が**工程IDを失って宙に浮く**（`作業.工程ID` が存在しない）。集計はその作業を数えない（`DB.byP[pid]` が無いため）。画面で追加した工程（エムネットの枠が空）は、次の取り込みで「工程を消す」として消える。
3. エムネットで「完了を取り消した」「日時を空にした」は、画面に**反映されない**（空は上書きしない）。逆に、画面で押した完了がエムネットに無いままだと、ずっと残る。
4. 取り込みは**全体を1回で戻す仕組みが無い**（品目300件ずつ別々に保存）。途中で止まると半分だけ入る（手順書は「保存できた分は残る」と明記）。
5. ごみ箱の `中身` に案件・工程のJSONを入れる。1セル5万文字の上限（スプレッドシート）に、工程が多い品目で近づく恐れ。
6. `OPS`（操作の札の記録）を Script Properties（1つの値は約9KB）に300件入れる。1件約17文字×300＝約5KB。札が長くなると上限に近い。
7. `canRetry` は「エラー文に日本語があれば断られた」と決めつける（HTML:1403）。通信・Googleの側のエラーが日本語で返る環境では、**つながらないだけなのに「保存できなかった操作」に回る**恐れ（実際の文言は未確認）。
8. 開始・完了の時刻は**端末の時計**（`stamp()`）。端末の時計がずれていると、そのまま入る。日付はタイムゾーン無しの文字。
9. 作業ログの「同じ行」判定は、行の中身（時刻・作業者・数）のハッシュ的な文字列。エムネットで行を**直す**と別の行として**二重に入る**（前の行は残る）。在庫の写しは「前に写したのに今のCSVに無い行」を警告するが、作業ログには警告が無い。
10. `setHolidays` は ver の比較も操作の札も使わず、**休日を丸ごと入れ替える**。同時に誰かが休日を足していても失われる。実績記録にも残らない。
11. 全部の操作が**全体で1つのロック**。1回の操作ごとに工程・案件・品目・出荷・在庫の動き・作業のシートを全部読む（GS:435-443）。データが増えるほど遅くなる。画面側も全データを持つ。
12. 比べの印（ハッシュ）は32ビットの簡易方式（GS:793）。衝突はまれだが理屈の上ではある。
13. 作業者名が「ローマ字」「打ち間違い」で70通り以上ある（手順書）。名寄せしても、**書き換わらない場所**（作業・出荷・実績記録）は、集計の画面だけでそろえて数える。新アプリでは名前の持ち方（ID参照にするか）を決める必要がある。
14. 6段目の不具合（出荷の工程を41件以上まとめて完了すると新しい行が消える）は7段目で直ったと注釈にある（GS:449）。新アプリでは同種の「一括書き込みで行が消える」心配は無いが、同様のテストは要る。

### 6-4. 仕様の食い違い・おかしな点

- 古い案件：手順書は「2024年より前」、コードは「2025年より前」（2-8）。
- 手順書とコードで「出荷待ち」の意味がずれる：手順書は「出荷待ち」、コードは「出荷の工程が未完了の品目の残数（まだ始まっていない品目も含む）」（3-6）。
- バーコードが数字だけでない行は警告だけで取り込まれる（飛ばさない。2-4）。手順書は「壊れる」とだけ書く。
- `setHolidays` には操作の札がある（引数にある）が使われていない（二重送信を防げない）。
- 基準時間：手順書の注意で「工程全体の分とみなしている（単位は未確認）」。コードは分として扱う（`fmtMin(x.std)`）。
- 工程が0個の品目：`_done` が偽になるので、状態の絞り込みで「終わっていない」と「すべて」には出て、「全部終わった」には出ない。今の工程が無いので、まとめて完了のチェックも出ない。
- 手順書は「CSVの1行目の中身」について書いていない（コードも読み捨て）。

## 7. 新アプリへの示唆（参考）

- 判定関数は1か所（サーバー）に集める。画面は「先読み」したければ同じ関数を共有（TypeScriptなら同じパッケージ）。
- D1 では、**文字だけの表**ではなく型を付けられる。日時は ISO＋タイムゾーン（日本時間）を決める。
- 状態は日時から導く方式をそのまま持てる（列を足さない）か、SQLの集計で `今の工程` を出す方法を設計する。
- 論理削除（取り消した日時）と実績記録（変更履歴）は今のまま持つ価値が高い（監査・取り消し）。
- 名寄せは「文字の置き換え」から「名前マスタへのID参照」にできる（作業・出荷・実績記録も揃う）。ただし、エムネットCSVの書き方は文字なので、取り込み時の置き換え表は必要。
- 操作の札（opId）による冪等と、`baseVer`／ハッシュによる楽観的ロックは、D1の `UNIQUE` 制約・`UPDATE … WHERE` で置き換えられる。
- 認証：Cloudflare Access（社外から確認するのが社内の決まり）＋作業者の自分選択か、ログイン者に紐づけるかを決める。
