## 工程管理（koutei-kanri-app）仕様書

最終更新：2026-11-04（4段目：基本の一覧・集計・案件・ガント）

### 目的
受注（エムネットの案件・品目）が、いまどの工程にいるかを一目で見る。
今はエムネットと並行して使う。エムネットの案件一覧CSVを毎日取り込み、エムネットを正として写す。
あとで、オービックの受発注システムの受注データも毎日取り込み、工程と並べて見られるようにする（ミラーの場所をオービックOAに確認中）。

### 元にしたもの
川﨑部長の試作「工程管理（エムネット置き換え 試作①）」7段目c（Apps Script＋Googleスプレッドシート、画面の版0.7.2）。
試作のシート12枚を、同じ意味の表にした（`migrations/0001_init.sql`）。試作のデータは、あとでこのアプリに移す（平田さん決定 2026-11-03）。

| 試作のシート | このアプリの表 |

| 案件・品目・工程・作業 | cases・items・processes・works |
| 実績記録・出荷・在庫の動き | action_log・shipments・stock_moves |
| 基本の一覧・休日・設定 | masters・holidays・settings |
| 取り込み履歴・ごみ箱 | import_history・trash |

### 1段目（2026-11-03）でできること
1. **CSV取り込み**（管理者だけ）：エムネットの案件一覧CSV（カテゴリー2＝製造技術で絞る）を選ぶ → 今のデータと比べて「新しい・変わる・変わらない・CSVにない」を出す → 選んで取り込む。
   - 比べ方・飛ばす行・古い案件（納期が2025年より前で終わった工程が無い）・名寄せ・エムネットの日時で上書きするきまりは試作と同じ。
   - 試作と違う点：比べるのも書くのもサーバー。**1回のまとまりで書く**ので、途中で止まって半分だけ入ることが無い。間にデータが変わっていたら比べ直す。
   - 「CSVにない」は、チェックしたものだけ消す。消したものはごみ箱（trash）に中身を丸ごと残す。
2. **工程一覧**（全員）：1行＝品目1つ。工程を順番どおりに札で並べる。済（緑）・中（黄）・次（青い枠）・まだ（灰）。外注・出荷の工程には字を付ける。納期遅れは左の赤い線と「（遅れ）」。
   - 上の「いまどの工程にいるか」に、今の工程ごとの件数を出す。押すとその工程の品目だけに絞る。
   - 絞り込み：さがす・状態（終わっていない／全部終わった／すべて）・納期遅れだけ・隠したもの。端末ごとに覚える。
   - 品目を押すと、工程の表（担当・機械・予定・開始・完了・完成数量・不良数・コメント）が開く。
3. **操作ログ**（管理者だけ）：CSVの取り込みを記録する。

- 試作の「次の番号」「次のバーコード」「在庫の正」を引き継ぐ（同じ番号を二度使わないため）。
- 2026-11-04 に手元のデータベースへ入れて件数を確かめた：案件219・品目221・工程1,489・作業4・実績記録148・出荷2・在庫の動き3・基本の一覧17・取り込み履歴2（スプレッドシートと一致）。
- ⚠ JSON とSQLには客先名・単価が入るので、リポジトリには置かない（`Cowork\_work_temp\エムネット置き換え_川崎版7c\`）。
- 本番に流すのは最初の1回だけ。並行運用中は試作のデータも増えるので、本番に出す直前に読み直してから流す。
- ごみ箱の「中身」は試作の行（配列）のJSONのまま。戻す機能を作るときに読み替える。

### 2段目（2026-11-04）でできること
工程一覧の札を押すと、その品目の下に小窓が開く（Access を通れた社員は全員押せる）。
- **工程の開始・完了・取り消し・コメント**。完了には完成数量（良品）・不良数・不良の理由を入れる。開始を押さずに完了してもよい（開始も同じ時刻で入る）。
- **出荷の工程の完了**は出荷を1件記録する（出荷日・配送業者・伝票番号・在庫から）。分納と出荷の取り消しは3段目。
- **工程の中の作業**（何回でも・何人でも）：作業を始める／終える（完成数・不良数・機械・コメント）／終わった作業をあとから記録／直す／取り消す。作業の合計が工程の完成数量・不良数に入る。作業を終えても工程は自動では完了しない。
- **まとめて完了**：行の左のチェックで選んだ品目の「今の工程」を、品目の数量でまとめて完了（1件でも誤りがあれば全部やめる）。
- 在庫の動き：製品になる工程（出荷の1つ手前）の完了で製品が増え、取り消しで戻る。出荷で減る。在庫から出した品目は増やさない（試作と同じ）。
- 上に「○○さんの作業中」を出す。押すとその工程の小窓が開く。
- 画面は1分ごとに更新番号だけを確かめ、ほかの人が変えていたら読み直す。

**試作と違うところ**
- **作業者＝ログインした人**（全社マスタの名前を、基本の一覧の名寄せでそろえる）。他人の名前では押せない。ほかの人の作業を終える・直す・取り消すのは管理者だけ。
  - 部署で共有しているメールでログインしたときだけ、画面の上で作業者を選ぶ（基本の一覧に作業者があればその中から。端末ごとに覚える）。
- 押した時刻はサーバーの時計（端末の時計がずれていても同じ）。
- 送信待ちの列（つながらない所で押しためる）は持たない。つながらないときはその場で知らせる。同じ操作が2回届いても1回分にする（操作の札）。

### 3段目（2026-11-04）でできること
- **出荷**（全員）：工程の小窓と「出荷」の画面で、出荷日・数・配送業者・伝票番号・荷物の個数・時間指定・お届け先・担当者・備考・作り置きの在庫から、を入れて記録する。
  - 「これで全部」あり＝出荷の工程を完了（完成数量＝出荷した数の合計）。なし＝分納（工程は作業中のまま、何回でも）。数が残りに届かない／届いたのに「これで全部」が無い、ときは確かめる。
  - 出荷を1件ずつ取り消せる（工程の完了はそのまま）。出荷の工程の「完了を取り消す」は、その工程の出荷も全部取り消す。
  - 「出荷」の画面：出荷予定（今日まで・今週・来週まで・まだ出荷していない全部。予定日＝出荷の工程の納期→開始予定→品目の最終納期）と、出荷の記録（新しい順・取り消したものも出す）。
- **在庫**（見るのは全員・直すのは管理者だけ）：図面番号ごとに エムネットの写し／この画面の計算／差／仕掛品／出荷待ち。★の列が正しい数（在庫の正）。行を押すと仕掛品の内訳・増えた減ったの履歴（300件）・数を直す（理由は必ず）・エムネットの数に合わせる。在庫の正の切り替えも管理者だけ。
  - 試作と違う点：試作は誰でも数を直せた。数を勝手に変えられないよう管理者だけにした。
- **エムネットの作業ログCSV**（管理者だけ・CSV取り込みの画面）：1回読み込むと「①作業を写す」と「②完品在庫数を写す」をまとめて確かめて写す（試作では別々の画面だった）。行の印（もと）の作り方は試作と同じなので、試作で写した行とも二重にならない。最初の数（この画面の計算のもと）も入れられる。

### 4段目（2026-11-04）でできること
- **基本の一覧（名寄せ）と休日**（管理者だけ・メニュー「基本の一覧」）：工程名・作業者・機械・外注先・顧客・不良の理由。似た書き方の候補（全角半角・大文字小文字・記号の違い）・選んでまとめる・一覧に無い名前（「無」）を足す・直す・外す・よくある不良の理由を入れる。保存すると今ある案件・工程の名前もそろえる（試作の applyMaster_ と同じ）。休日は1日ずつ足す・外す。
  - 試作と違う点：試作は誰でも直せた。今あるデータをまとめて書き換えるので管理者だけにした。休日のファイル（リバテック休日.txt）で丸ごと入れ替える機能はまだ。
- **集計**（全員・メニュー「集計」）：期間・まとめ方（工程名・図面番号・作業者・機械・不良の理由・顧客・日・月）・並べ方・しぼり込み。作業時間・1個あたり・完成・不良・不良率・多い不良の理由。基準時間との比べ。CSVで保存・表をコピー。数え方は試作の sumFacts・sumGroups と同じ（エムネットから写した作業の10時間の上限・作業を分けずに完了した工程も入れる）。
- **案件**（管理者だけ・メニュー「案件」、工程一覧の品目の詳細の「この案件を直す」）：案件・品目・工程の並びの登録と修正（↑↓で並べ替え・工程を足す・消す・前回の並びを写す）、品目を消す（ごみ箱へ）、案件をごみ箱へ、ごみ箱から戻す。バーコード番号は保存のときに「20」＋連番＋チェック数字で付ける。きまりは試作の applyEdit_ と同じ。
  - ⚠ エムネットから来た品目を直しても、次のCSV取り込みでエムネットの中身に戻る。
  - 試作と違う点：試作は誰でも直せた。管理者だけにした。
- **ガント**（見るのは全員・直すのは管理者だけ・メニュー「ガント」）：横棒＝開始予定〜納期。済・中・遅れを色と字で。土日・休日は灰色、今日は青い縦線。2週・1か月・3か月、1週ずつ前後。棒を押して開始予定・納期を直す。「後ろの工程も同じだけずらす」「休日を数えない（稼働日でずらす）」。
  - 試作と違う点：試作は棒を引っぱって動かした。ここでは押して日付を直す（指で誤って動かさないため）。「元に戻す（1回）」「複数選んで動かす」はまだ。
